# 复盘：收反馈

**必做。** 出行结束后必问，不跳过。什么时候问、问几段、没回怎么办，见 `review/timing.md`；本文件只管问什么、怎么解码、写回哪里。

## 一、问四件，一次问完

不超过四问，用日常话，一轮问完，不拆成四轮。

| 问 | 想得到什么 |
|---|---|
| 哪一段她最有反应 | 兴趣点，决定下次主菜选什么 |
| 哪一段最没意思 | 排除项，写进黑名单或降低权重 |
| 她自己问了什么 | 最好的价值层证据，比任何自评都准 |
| 下次想换什么 | 品类轮换的方向 |

12–18 岁档换问法：

| 问 | 想得到什么 |
|---|---|
| 哪一段你觉得值 | 议题是否成立 |
| 哪一段是浪费 | 排除项 |
| 你自己做的哪个决定最有用 | 决定权是否有效 |
| 下次想去哪类 | 方向 |

**不问**「满意度几分」「体验好不好」。分数没有信息量，也无法写回。

## 二、反馈怎么解码

反馈是原话，不是评分。三类要分开处理：

**明确反馈**：「她在那面铜钱墙前站了十分钟」→ 写兴趣点，下次优先同类。

**否定反馈**：「后面那个厅她一直在看手机」→ 写排除项，下次不再排那种节奏。

**无反馈**：「还行」「挺好的」→ 不写任何偏好。记「本次无有效反馈」，不推断。

**不许做**：把「还行」解释成「喜欢」，把没说话解释成「没兴趣」。

## 三、写回哪两处

**`knowledge.json` 的 `reviews`**：本次实际反馈、日期、方案 ID、有效或无效。

**`knowledge.json` 的 `visited`**：只有实际去过才写。推荐过、选中过、没去，都不算。

**`family.template.json` 的 `interests` 与 `avoid`**：只写有原话支撑的，标注来源与日期。

## 四、跨周清账

上周的待出行方案：

- 明确去了 → 转 `visited`，等反馈。
- 明确没去 → 记原因（不给原因就记「未说明」），不猜。
- 没消息 → 记「结果未知」，保留在 `plans` 里，不计入配额，不假设去过。

## 五、反馈之后做什么

1. 按反馈更新知识库。
2. 问一句「要不要现在生成这次的页面」。
3. 要，就进 `review/animate.md`。
4. 不要，停止。不劝第二次。

**出图不是强制的。** 家长可能只想留个记录，或者根本不想再看一遍。

## 六、状态词

反馈本身只用四个状态：有效反馈 / 无效反馈 / 结果未知 / 未去。

页面生成另用：已生成 / 未生成 / 失败 / 已跳过。
