# 反馈时机：什么时候问「玩得怎么样」

**这一份是本 skill 的核心。** 方案交付出去不算完，问对了时机、拿到真实感受、结成一张图，一个闭环才算走完。

问早了，孩子还在车上，答不出；问晚了，细节全忘，只剩「还行」。**时机错了，等于没问。**

## 一、硬规则

**每次交付方案，必须同时建一个反馈提醒。** 不许只在方案末尾写一句「回来告诉我感受」，那不算。

- 用宿主原生的定时任务能力，建一次性任务（`fireAt`），不是周期任务。
- 任务 ID 与触发时刻写进 `knowledge.json` 的 `pending_reminders`。
- 任务失败或宿主不支持时，如实说「提醒未建成」，并给一条可手动设置的路径，不假装成功。

## 二、按到家时间定时

输入只有一个：**预计到家时间**。其余按表推。

| 到家时间 | 什么时候问 | 为什么 |
|---|---|---|
| 早于 12:00 | 当天 17:00 | 午睡起来，晚饭前，还记得住 |
| 12:00–15:59 | 当天 19:00 | 吃过晚饭，人缓过来了 |
| 16:00–17:59 | 当天 20:30 | 睡前，21:00 前问完，不拖着睡觉 |
| 18:00 及以后 | 次日 10:00 | 当天太累，问了也是敷衍 |

**先查表，表优先。** 「延迟约 5 小时」是这张表的来由，不是独立算法。所以 11:30 到家问的是 17:00，不是 16:30；20:30 到家问的是次日 10:00，不是 01:30。

推算用 `scripts/remind_at.py`，不手算：

```bash
python3 scripts/remind_at.py 2026-11-27 16:20   # 输出 2026-11-27T20:30:00
python3 scripts/remind_at.py --test             # 八条边界用例
```

改表时同步改脚本里的 `remind_at()` 与 `CASES`，跑一遍 `--test` 全 OK 才算改完。

## 三、静默窗口

问询只落在 **09:00–21:00** 内。

- 算出的时刻早于 09:00 → 顺延到当日 09:00 后最近的整点。
- 算出的时刻晚于 21:00 → 顺延到次日 10:00。
- 用户明确说过「那个点我在上班」「晚上不方便」→ 按他给的空档重排，不问第二次。

## 四、问什么、分几段

四个问题，分两段问，不一次砸过去。

**第一段，当晚或次日，孩子还在的时候，随口问两句：**

1. 今天哪一段她最有反应？
2. 她自己问了什么？

这两问孩子能听见，问法自然，不算审问。

**第二段，孩子睡了以后，问家长两句：**

3. 哪一段最没意思？
4. 下次想换什么？

第 3 问不在孩子面前问。当着他的面说「哪段最没意思」，会让他觉得这趟被打了分。

## 五、惊喜机制：说什么，换什么

反馈不是义务。给一个真的东西作交换，比催三遍有用。

**惊喜就是卡片本身，分三档。** 说了多少，卡片就有多厚。

| 说了什么 | 拿到什么 |
|---|---|
| 只说一句「玩了什么」 | 简版卡：一张封面帧，日期、地点、一句话 |
| 说清哪段最有反应、哪段没意思 | 完整卡：加时间轴、加「最有反应的一段」 |
| **让孩子本人说一句** | 完整卡，再加一栏「她说的」，原话印上去，署她的名字 |

第三档是这套设计的关键。孩子听见自己的话被印在一张图上，比家长问十遍都管用。

**惊喜的真实性**：三档都能兑现，不许许诺兑现不了的东西（优惠、积分、抽奖一律不碰）。承诺了就出。

**怎么开口**：把交换说清楚，一句话，不绕弯。

> 今天玩了什么，说一句就行——你要是让她自己说一句，我把她的话原样印在卡片上。

**孩子那一句怎么拿**：让她自己讲，不用纠正，不用引导到「正确答案」。讲得乱、讲得短、讲得跑题都行，原话照录。**跑题的那句往往最好用。**

**红线**：
- 不给孩子的回答打分、评好坏、比长短。
- 不把惊喜变成条件去逼孩子说「有意义」的话。
- 孩子不想说就不说，卡片降到第二档，不追问。

## 六、没回怎么办

**只催一次，间隔 24 小时。**

- 原定时刻：问完整四问。
- 24 小时后：只问一句，带一次惊喜的口子：「昨天那趟，说一句就行——让她自己讲一句，我印到卡上。」
- 再无回应：不再打扰。记「结果未知」，写进 `knowledge.json`，不进任何统计。

催第二次会把提醒变成讨债。家长想补，自己会说。

**未成行的情况**：提醒触发时先问一句「去了吗」。答没去或没安排，记「未去」，追问原因一句即可，不猜、不劝，直接结束，不生成页面。

## 七、收到反馈之后

顺序固定，不跳步：

1. 把原话分三类写回：明确反馈、否定反馈、无反馈（见 `review/collect.md`）。
2. 写 `visited`，只记实际去过。
3. 生成 `card.json`，六字段齐。
4. 按方案同一套皮肤渲染页面。
5. 给家长看，问一句「这样可以吗」。
6. 确认后导出 JPG。
7. 存档，把 `pending_reminders` 里这条标为已完成。

**反馈没到手，不出图。** 没有真实感受的卡片只是计划复述。

## 八、跨天行程与特殊情形

**两天行程**：只在第二天结束后问一次，按第二天的到家时间算。不每天问。

**当天下雨改了方案**：仍按原定时刻问，多问一句「后来改成什么了」，写进 `visited` 的实际内容。

**孩子中途生病、提前回家**：按实际到家时间重排提醒。任务用更新，不新建。

**改期**：更新原任务的 `fireAt`，不建第二个。台账与 `pending_reminders` 同步改。

## 九、语气

提醒触发时的开场只有一句，不寒暄：

> 昨天那趟回来，哪一段她最有反应？

不用「打扰一下」「方便的话」。家长知道是自己设的提醒。

## 十、自检

1. 方案交付时，提醒是否已建，任务 ID 是否落盘。
2. 触发时刻是否落在 09:00–21:00。
3. 四问是否分成两段，第 3 问是否避开了孩子。
4. 是否只催一次。
5. 没有反馈时，是否确实没有出图。
6. 惊喜是否兑现，档位是否与收到的内容对得上。
7. 孩子那一句是否原话，有没有被改写成「大人话」。
